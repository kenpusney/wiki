> 本文创作于2018年3月28日，是轻故事 [之前一篇](https://mp.weixin.qq.com/s?__biz=MzI0OTQxNjQ4MA==&mid=2247484011&idx=2&sn=184dab22e5b7e84772d91fd65dc8fc9e&scene=21#wechat_redirect) 的后续。
> 
> ⚠ 故事内容纯属虚构

“几年前我就考虑过枚举这个东西。”

“你知道，我不是科班出身的，可能看事情没你们那么有深度。我真的没有像你们那样深入地学习过 C 语言，所以我对 C 语言风格的枚举并没有那种蜜汁情怀。”

“可是后来我发现，如果你能有效利用的话，枚举确实是一个好东西。C++11 里面 enum class 成了强类型的，这样能够限定死枚举的定义域而且能够避免歧义的转换了；Java 里面甚至能够把枚举值做成结构化的了；后来有一段时间网上人人都在吹 Haskell 的时候，我知道了 GADT 这东西，再加上 Rust 和 Swift 进一步的推广，真的进一步颠覆了我的认知。”

“有时候我甚至觉得，程序里面只剩下枚举和模式匹配才好呢。”

“可是，你应该也知道，这些语言里面没有一个是尽善尽美的。即便是有些已经能够达到我的期望了，一些既定的坑也会让我不得不放弃他们。你看知乎那个刘雨培，整天沉溺于比较语言特性，干了些什么正经事情。”

“所以后面我就在想，这样子折腾自己的话不是个办法。要么你做到最好，要么干脆就别搞。与其反复纠结枚举这个东西的设计，不如直接找一个跟他完全不想关的语言去用。当然了，也就只有 Go 可以选择了。”

“现在你又提到枚举，我权且当做是对我的选择的一种挑战吧。刚才我也细想了一下，才发现其实 Go 其实也面临同样的问题。”

“没错是没有枚举了，但是却加了更诡异的方法来实现等价的功能，而且还是没能完全消除 C 枚举的缺点。”

“所以我猜你所说的实现枚举功能，并不只是简单的考察我做编译工具的能力。”

“我觉得我就有必要先从你这里获得一些提示了。”

“既然你希望我实现枚举，至少可以确定的是，我们对 Go 现在的解决方案都是不满意的：表现力不足；不够类型安全；不能有效限制定义域。”

“那么我大概对你的要求也有一个比较清晰的概念，也有一个大致的框架设计了。”

“所以，到底应该是值类型还是引用类型？”
