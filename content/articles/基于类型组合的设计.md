2001 年，著名魔法师 Andrei Alexandrescu 出版了那部改变了很多人思路的小册子，Modern C++ Design，两年后由候捷和於春景两位老师翻译后在国内出版，译名《C++设计新思维》。

这本书里 Andrei 提出了一种新的设计思路，policy-based class design（这个词一直都没有对应的中文，至少在候捷老师的书里面我没看到，某些特定的名词他是不会翻译的），通过模版参数和静态分发来组合实现原有动态分发做不到的更加灵活的设计模式。

但是这个设计思路对场景的要求和设计能力要求不是一般的高：

- 首先对于要解决的问题你要能够 **拆分** 出不同类型的策略；
- 其次是不同类型策略间的 **正交性** 要足够好；
- 另外就是，同样类型的策略要能够 **充分** 满足解决问题的要求。

所以这套新思维也就没能够推广起来，再加上后来的 C++社区开始探索在原有的语言特性限制下能有什么新突破（当然某些突破点也来自于 Andrei 的这本书和他后来领导的 D 语言社区）。但进一步其实大家发现了这个思路的简化版。

虽然我拆分策略是不太行，至少我在业务层面上拆分依赖是可以的。那不同的依赖也就可以像 Andrei 那样通过模版参数来注入，通过静态分发来组合成最终想要的效果。这样依然能够做到非常灵活，而且这个注入过程是编译时完成，脱离了运行时容器带来的 runtime overhead。我在 [[Dependency Injection Made Simple]] 里面也提到过这个思路。

要说还是 Andrei 牛，毕竟到 Martin Fowler 写他那篇知名的依赖注入文章都是 2004 年的事儿了。

但就像是我在前面泛型的文章里面提到的，这种操作在基于模版的 C++里面可行，到了 Java 这种类型擦除的泛型里面，就做不到了。Java 的泛型参数是无法携带传递进来的类型信息的，只能作为类型标注。这就带来一个问题，如果我希望组合不同类型实现逻辑的时候，就只能通过手动一个个的来拼凑。

一个实际的例子是我在之前的基础库里实现的 MultiMap。

其接口如下：

```
public interface MultiMap<K, V> extends Map<K, Collection<V>> {

  int keyCount();

  int valueCount();

  V put1(K key, V value);

  Collection<V> putMany(K key, V... values);
}
```

这里并没有参考 Guava，而是简单的组合了一下 Java 的类。本来我也不太想因为一个复合集合就引入一个巨型库。

MultiMap 的思路很简单，内部也就是把 Map 和 Collection 组合起来。但问题来了，Map 的实现有很多种，Collection 的实现也有很多种，如果我要实现这个接口，还想用到其他集合的特性，就只好针对不同集合的组合一一实现。

```
class LinkedHashMultiMap { ... }

class TreeMapHashSetMultiMap { ... }

class ConcurrentHashMultiMap { ... }
```

然而除了这些类型不同之外，本身的实现逻辑没有太大区别。如果是原有的面向对象设计思路，肯定是做一个 AbstractMultiMap 实现大部分逻辑，然后每个都继承自他，替换具体类型的那一部分就好。

但这还是无法做到自由组合，每次出现一个新的组合都需要去继承 AbstractMultiMap，自己重新实现逻辑。

要达到自由组合的目标，自然是希望一个 MultiMap 的实现能够接受我传递过去的集合类型，然后对应使用这部分的集合。换句话说，就是我们通过某种方式把我们的“类型”作为某种方式“注入”到实现里面去。这里我们就硬性把类型变成了一种依赖，在 C++ 自然可以做到，Java 里面要怎么做呢？

我们先来看 Java 8 以后的构造方法的这样一个性质：

本质上，一个构造方法是 `(V...) -> (? super T)` 这样一个函数， `V...`是该构造方法所需要的参数，如果没有任何参数，则可以是一个 `Supplier<? super T>` 。

比如 `HashMap::new` ，其实就是 `Supplier<HashMap<?>>` ，当然也是 `Supplier<Map<?>>` 。

而我们通过持有 `Supplier<Map<?>>` 对象，可以根据其对应的构造方法就能产生任意想要获得的 Map 实现。于是进一步我们的 MultiMap 可以变成：

```
class MultiMapImpl<K, V> implements MultiMap<K, V> {
  Map<K, Collection<V>> map;
  Supplier<Collection<V>> collectionSupplier;

  MultiMapImpl(Supplier<Map<K, Collection<V>>> mapSup,
      Supplier<Collection<V>> collectionSup) {
    this.map = mapSup.get();
    this.collectionSupplier = collectionSup;
  }
  ...
}
```

使用起来自然也很简单

```
MultiMap<Integer, Integer> treeMapHashSetMultiMap =
    new MultiMapImpl<>(TreeMap::new, HashSet::new);
```

类似的思路一样，类型擦除给我们带来了一部分麻烦，但通过 Java 8 的方法引用和函数式接口，还是能够做出一些比较方便的类型层面组合的操作。
