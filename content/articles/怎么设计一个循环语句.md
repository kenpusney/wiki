这事情源自于我的一个脑洞。

在很早之前我就在想，能不能设计这样一种循环语句，既不用加入什么 mutable 的操作，又能胜任大部分使用循环的场景。因为最早我糊的一个玩具语言里面就没有循环，导致很多东西不得不用奇怪的递归来搞。

当然说到递归就不得不提一下之前的函数式文章里那个 accumulator passing 相关的递归改写了。通过反复对比我发现，是不是可以同样利用这个思路搞一下。

于是折腾了一番以后就出现了下面的设计。（当然了按照我在某群里的讨论，大家一致认为还是递归看起来更简单直观）。

整个结构如下：

```
loop [<initializers>] [with <initialiers>] do {
  [ <statements> |
    <yield statement> |
    <accumulate statement> |
    <next statemenet> ]+
}
```

`loop` 会初始化一系列变量。说是变量其实他们都是 immutable 的，不可能在 `loop` 里面被修改。 `loop` 的初始化部分分为两块， `with` 之后是另一部分，与 `loop` 部分不同的是， `with` 部分主要用来做 accumulating。

accumulating `loop` 和常规的 `loop` 不同的是返回结果是 accumulating 的结果，而非常规 `loop` 中 `yield` 的集合。

这里就不得不提 `loop` 体里面的内容，常规的语句，和 `loop` 中特定的语句：

- `yield` 类似于 Scala 中的 yield，会返回一个值，并最终集合起来作为整个 `loop` 的值返回，
- `accumulate` 则是用来更新 `with` 中的变量，总是与 `with` 一并出现。而这个时候 `loop` 的结果就是 `accumulate` 最终执行时的结果，
- `next` 则相对简单，就是主动控制下一次 `loop` 中 `loop` 部分变量的值。

举个例子。

常规写法：

```
let fact x = 
  let rec fact_iter i prod =
    if i > x then prod
    else fact_iter (i + 1) (prod * i)
  in
  fact_iter 1 1;
```

使用了 loop 以后：

```
let fact x =
  loop i = 1 with prod = 1 do {
    if i <= x {
      accumulate prod * i
      next (i + 1)
    }
  }
```

前者就是套了个壳的基于 accumulator 的尾递归。而后者其实也很简单，就是把尾递归拆了一下，变成了某种特定的结构。通过 `next` 和 `accumulate` 分别来更新 `loop` 和 `with` 处的绑定。

以 `fact 5` 为例，

- 第一次循环， `i = 1` ， `prod = 1` ，因为 `i <= 5` 成立，进入 `if` 分支， `accumulate` 更新下一次循环的 `prod` 为 `1 * 1` ， `next` 更新下一次循环的 `i` 为 `1 + 1` 。
- 第二次循环， `i = 2` ， `prod = 1` ，分支条件成立，更新 `prod` 为 `1 * 2` ， `i` 为 `2 + 1` 。
- 第三次循环， `i = 3` ， `prod = 2` ，分支条件成立，更新 `prod` 为 `2 * 3` ， `i` 为 `3 + 1` 。
- ……
- 第六次循环， `i = 6` ， `prod = 120` ，分支条件不成立，退出循环并返回 `prod` 的值 `120` 。

与一般循环不同的是，这里在循环头部没再有条件判断，也不会存在主动退出循环的操作。反过来，是否要进行下一次循环才是让手动控制的。换句话说，上面 `loop` 版本的 `fact` ，如果没有进入 `if` 的分支的话，那根本就不会进行下一次循环，而是自动把上一次 `accumulate` 的结果返回了。

我们再看其他的几个例子。

前面说过当遇到 `next` 的时候会进行下一次循环，这个过程甚至是可以无条件的，于是一个死循环写起来也就非常简单：

```
let forever f =
  loop do {
    f ();  # invoke \`f\`
    next;  # next iteration
  }
```

另外再比如 map

```
let map f list =
  loop list do {
    if not (List.empty list) {
      yield f (List.hd list);
      next (List.tl list);
    }
  }
```

再比如一个无限长的 `List` 生成器：

```
let gen start = loop start do {
  yield next (start + 1);
}
```

当然这里需要一些惰性求值的特性才能实现，不过从结构上来说确实也相对简单很多了。

为什么要搞这么奇怪的 `loop` 呢，主要是出于两个动机。

- 首先是这样就能避免非得强行加入 mutable 的操作了，按照某种思路，rebind 不算 mutable，所以用 `next` / `accumulate` 这种方式可以让不可变循环看起来更自然。
- 另外就是不用考虑糊尾递归优化了，因为大概率大部分为递归都能用这个结构改写，那既然大家都费劲心思想怎么糊尾递归，不如直接糊这个 `loop` 好了。
