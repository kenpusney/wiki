
System Metaphor is an [[Extreme Programming|XP]] practice where the team creates a simple shared story that explains how the system works. It provides a common vocabulary and helps everyone understand the architecture.

## What is a System Metaphor?

A system metaphor is a simple analogy that describes the system's architecture and behavior. It's not a detailed technical document — it's a mental model that helps everyone communicate.

## Examples

| System | Metaphor |
|--------|----------|
| E-commerce | "A digital shopping mall" |
| Social media | "A town square where people gather" |
| Banking | "A vault with tellers and ledgers" |
| Search engine | "A librarian who knows every book" |
| Version control | "A time machine for code" |

## Why System Metaphors Matter

### Common vocabulary
- Everyone uses the same words to describe the system
- Reduces misunderstandings
- Makes onboarding faster

### Architecture guidance
- Guides design decisions
- Helps new team members understand the system
- Provides a framework for thinking about problems

### Customer communication
- Customers can understand the metaphor
- Facilitates discussion about features
- Makes technical concepts accessible

## How to Create a System Metaphor

1. **Gather the team** — Include developers, customers, and stakeholders
2. **Ask "What is this system like?"** — Brainstorm analogies
3. **Choose the best fit** — Simple, accurate, memorable
4. **Write it down** — Document the metaphor and its implications
5. **Use it** — Refer to the metaphor in discussions and documentation

## When to Update the Metaphor

- When the system's architecture changes significantly
- When the metaphor no longer fits
- When new team members struggle to understand it
- When the metaphor leads to poor design decisions

## System Metaphor and XP Practices

- **[[Simple Design]]** — The metaphor guides simple, consistent design
- **[[Collective Code Ownership]]** — Everyone understands the system through the metaphor
- **[[Pair Programming]]** — The metaphor provides context for pairing discussions
- **[[Refactoring]]** — The metaphor guides how to restructure code
