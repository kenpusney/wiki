
A Feature is a piece of work in [[SAFe]] that delivers business value. Features live in the Program Backlog and are broken down into [[User Stories]] at the team level.

## What is a Feature?

A Feature is a service or capability that fulfills a stakeholder need. Each feature includes a benefit hypothesis and acceptance criteria.

### Feature vs [[User Stories|User Story]]

| Aspect | Feature | [[User Stories|User Story]] |
|--------|---------|--------------------------|
| **Scope** | Large capability | Small, implementable piece |
| **Level** | Program level | Team level |
| **Owner** | Product Management | Product Owner |
| **Estimated** | T-shirt sizing | [[User Story Points|Story points]] |
| **Duration** | Multiple Sprints | Single Sprint |

## Feature Lifecycle

1. **Identified** — Added to the Program Backlog
2. **Defined** — Described with benefit hypothesis and acceptance criteria
3. **Estimated** — Sized using T-shirt sizing or story points
4. **Sequenced** — Prioritized for implementation
5. **Built** — Broken into [[User Stories]] and implemented
6. **Validated** — Tested and verified against acceptance criteria
7. **Released** — Delivered to users

## Feature in SAFe

In [[SAFe]], features are part of the program-level artifacts:

- **[[Epic]]** — Portfolio level (larger than features)
- **Feature** — Program level
- **[[User Stories|User Story]]** — Team level

Features flow from the Program Backlog into Sprints where they are broken down into stories.
