
The Planning Game is an [[Extreme Programming|XP]] practice for collaborative planning between developers and customers. It's not a game in the recreational sense — it's a structured conversation about what to build and when.

## How the Planning Game Works

### The two sides

- **Business side** (Customer/Product Owner): Decides *what* to build and *why*
- **Development side**: Decides *how* to build and *how long* it will take

### The process

1. **Write User Stories** — The customer writes stories describing desired functionality
2. **Estimate stories** — Developers estimate effort using [[User Story Points|story points]]
3. **Plan iterations** — Customer selects stories for each iteration based on priority and team capacity
4. **Track velocity** — Team measures how many points they complete per iteration
5. **Replan** — Adjust plans based on actual velocity and new information

## Key Concepts

### Story Cards
Requirements are written on cards (physical or digital) following the format:
> As a [user], I want [action], so that [benefit]

### Story Points
Relative estimates of effort, not absolute time. See [[User Story Points]].

### Velocity
The number of story points a team completes per iteration. Used to plan future iterations. See [[Velocity]].

### Iterations
Short time-boxes (1-2 weeks in XP) where the team commits to completing a set of stories.

## Benefits of the Planning Game

- **Shared understanding** — Both sides understand what's being built and why
- **Realistic expectations** — Velocity-based planning is grounded in reality
- **Flexible** — Plans can be adjusted as new information emerges
- **Customer-driven** — The customer controls priorities
- **Transparent** — Everyone sees the plan and progress

## Planning Game vs Traditional Planning

| Aspect | Planning Game | Traditional Planning |
|--------|--------------|---------------------|
| **Requirements** | Stories, negotiable | Fixed specifications |
| **Estimates** | Relative (story points) | Absolute (hours/days) |
| **Planning** | Iterative, adaptive | Upfront, rigid |
| **Responsibility** | Shared | Project manager driven |
| **Change** | Welcomed | Managed/rejected |
